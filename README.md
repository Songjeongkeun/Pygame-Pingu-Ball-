# Pingu Ball

Python/Pygame으로 만든 핑구 공 게임입니다. 핑구 공을 좌우로 움직여 이글루에 도착하세요.
첨부된 「튜토리얼 스테이지.docx」의 맵을 재구성한 튜토리얼 10개와 일반 스테이지 12개가 있습니다.

## 일반 스테이지 문서 적용

「스테이지.docx」의 일반 맵 12개를 문서 순서대로 실제 충돌 지형과 장치로 구성했습니다.
기존 일반 맵 7개 및 이전 미리보기는 제거했습니다. 튜토리얼 10개의 지형과 자산은 유지합니다.

| 번호 | 이름 | 도착 지점 |
|---|---|---|
| 1 | 빙하 협곡 | 오른쪽 아래 |
| 2 | 얼음 계단 | 왼쪽 위 |
| 3 | 오르막 발판 | 오른쪽 위 |
| 4 | 움직이는 다리 | 왼쪽 아래 |
| 5 | 시계 탑 | 가운데 기본 블록 |
| 6 | 태양 사이로 | 오른쪽 위 |
| 7 | 점프와 대시 | 오른쪽 위 |
| 8 | 빙하 미로 | 왼쪽 기본 블록 |
| 9 | 고드름 다리 | 왼쪽 위 |
| 10 | 태양 협곡 | 오른쪽 아래 |
| 11 | 바다사자 계곡 | 오른쪽 아래 |
| 12 | 남극 대모험 | 오른쪽 하단 단독 기본 블록 |

배치 원본은 `assets/stages/layouts.json`, 게임용 생성기는 `pingu_ball/campaign.py`입니다.
기획서는 [바운스볼 게임기획서 v04](바운스볼_게임기획서_v04.docx)이며, 12절에 현재 게임의
튜토리얼 10개와 일반 스테이지 12개 이미지 및 변경된 배치를 수록했습니다. 별·생선 기획은 유지합니다.
문서 배치 원본은 [스테이지 문서](스테이지.docx)입니다.
문서에서 추출한 원본 그림은 `assets/stages/references/`, 실제 게임 미리보기는
`assets/stages/stage_01.png`~`stage_12.png`에 보관합니다. 8번과 12번은 가로 35칸이며,
나머지 맵은 가로 25칸입니다. 화면에는 전체 맵을 비율에 맞춰 표시합니다.

하늘색 점선만 시간 블록으로 해석하고, 하늘색 실선 및 회색 블록은 기본 블록으로 구성합니다.
흰색 작은 사각형 4개는 파괴 블록, 하늘색 작은 사각형 4개는 고드름입니다.
검은 실선의 순백색 블록은 이동 발판이며, 검은 점선과 원은 충돌 없는 이동 범위 표시입니다.
번개는 태양, 블록 둘레를 도는 십자 장애물은 56px 바다사자로 표현합니다.
별과 생선은 배치하지 않으며, 이글루 아래에는 기본 블록을 둡니다.

현재 물리로 닿지 않는 구간은 **기존 블록의 위치를 조정**했습니다. 추가했던 보조 발판과
상하 이동 발판은 제거했습니다. 일반 반동 96px, 점프 블록 144px 및 발판 개수는 유지하며,
4번 파괴 블록과 겹친 가시 1개만 제거했습니다.

- 3번: 기존 점프 블록 3개를 128px 높이 차이의 계단으로 배치했습니다.
- 3번 이동 발판: 두 칸 크기를 유지하고 왕복 거리를 448px로 늘렸습니다. 오른쪽 끝은 x=832까지 도달하며, 투명 범위 표시는 발판 전체의 양 끝에 맞춥니다. 3번의 가로 안내선은 표시하지 않습니다. 상단 발판에서 내려타고 가시 계단 왼쪽으로 내려갈 수 있습니다. `tools/verify_stage3.py`가 실제 시작점부터 도착까지 방향키 입력을 재생합니다.
- 4번: 첫 점프 구간의 두 점프 블록 높이 차이를 192px에서 128px로 줄이고, 위쪽 기본 블록 3개를 64px씩 오르는 계단으로 옮겼습니다. 대시 아이템은 마지막 계단 위에 두고, 왼쪽 아래 파괴 블록과 겹친 가시 1개를 제거했습니다. `tools/verify_stage4.py`로 시작점부터 이동 발판과 파괴 블록을 거쳐 이글루까지 입력을 재생합니다.
- 6번: 가운데 기본 블록과 오른쪽 도착 발판을 내려 이동 발판에서 올라갈 수 있게 했습니다. 이글루도 도착 발판과 함께 이동합니다.
- 7번: 기존 점프 블록 6개를 상승 경로로 재배치하고, 경로를 막던 태양 줄과 파괴 블록을 옮겼습니다. 점프 아이템은 상단 점프 블록 위로 이동합니다.
- 9번: 기존 파괴 블록과 마지막 점프·발사 블록을 낮추고 간격을 줄였습니다. 왼쪽 도착 발판과 이글루는 발사 높이에 맞춰 한 칸 내려갑니다.

일반 맵은 1번부터 순서대로 열리고 12번 뒤에 여행 완료 화면이 표시됩니다.
교체 전 일반 맵의 기록은 새 맵 기록과 섞지 않습니다. 저장 형식 4에서 캠페인을 구분하며,
기존 튜토리얼 완료 및 1~10번 최고 시간은 유지합니다.

## 실행

스테이지 선택 화면은 **튜토리얼 스테이지 10개**와 **일반 스테이지 12개**로 나뉩니다.
튜토리얼은 문서의 순서대로 파괴 블록, 점프 블록, 좌우 이동, 상하 이동, 시간 블록,
좌우 발사, 태양, 고드름, 바다사자, 점프와 대시 아이템을 배웁니다. 10개 모두 바로 선택할 수 있습니다.

기존 기본 조작 맵과 특수블록 체험 맵 37개는 제거했습니다. 비활성화했던 이미지 맵 50개의
데이터·미리보기·실행 옵션도 제거했습니다. 원본 기획 문서는 수정하지 않습니다.
원본 문서에서 추출한 시안은 `assets/tutorials/stage_01.png`~`stage_10.png`에 보관하고,
실제 충돌 지형과 장치는 `pingu_ball/special_lab.py`에서 구성합니다. 점프 높이로 닿을 수 없는
계단 간격은 현재 물리에 맞추며, 모든 기본 블록은 64×64px, 시작 공은 일반 반동의 최고점입니다.

`special_blocks_play.bat` 또는 `python main.py --lab`으로 새 튜토리얼 목록을 엽니다.
`python main.py --special 1`~`10`으로 바로 실행할 수 있습니다. 클리어 후 다음 튜토리얼로
진행하며, 마지막 맵을 마치면 목록으로 돌아옵니다. 자세한 맵 구성은 [튜토리얼 문서](docs/special_blocks.md)에 있습니다.

단독 실행파일은 `output/executable/PinguBall.exe`입니다. Python 설치 없이 더블 클릭하여 실행할 수 있으며, 기록은 실행파일 옆의 `save_data/progress.json`에 저장됩니다.

Python 3.10 이상에서 프로젝트 폴더를 열고 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Windows에서는 설치 후 `Pingu Ball 실행.bat`를 더블 클릭해도 됩니다. macOS/Linux에서는 가상환경 실행 경로를 `.venv/bin/python`으로 바꾸세요.

Windows 실행파일을 다시 빌드하려면 다음 명령을 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
& .\tools\build_exe.ps1
```

## 조작과 규칙

첫 화면·스테이지 선택·튜토리얼·일반 스테이지 목록에서는 `assets/audio/title_opening.mp3`의 오프닝 음악을
반복 재생합니다. 게임을 시작하면 멈추고, 메뉴로 돌아오면 다시 재생합니다. 첫 화면과
스테이지 선택 화면의 소리 버튼으로 배경음과 효과음을 함께 켜고 끌 수 있습니다.

실패하면 `assets/audio/fail_noot.mp3`의 첨부 음성이 재생됩니다. 소리를 끄면 음성도
재생하지 않으며, 빠른 연속 실패에서는 이전 음성을 멈추고 새 음성을 재생합니다.
발판에 착지해 반동하거나 적 밟기·파랑 반발로 튕길 때는 `assets/audio/bounce_seal.mp3`를
재생합니다. 수평·방향 발사와 벽 옆면 접촉은 반동음으로 처리하지 않습니다. 반동음은
겹치지 않게 재생하고 실패 시 멈춥니다.
이글루에 도착해 클리어하면 `assets/audio/goal_arrival.mp3`를 한 번 재생합니다.
도착음 재생 시 이전 반동음·실패 음성은 멈추며, 소리 끄기 설정을 함께 적용합니다.

- 첫 화면은 제공된 `assets/title_screen.png`를 비율을 유지해 표시합니다. 이미지의 **게임 시작** 버튼을 클릭하거나 Enter·Space를 누르면 스테이지 선택으로 이동합니다. 선택 화면의 **메인 화면** 버튼이나 Esc로 첫 화면에 돌아갑니다.
- 왼쪽·오른쪽 방향키: 공중에서도 좌우 가속 이동. 놓으면 감속하며 동시 입력은 무입력입니다.
- R 또는 재시작 버튼: 확인 없이 처음부터 재시작합니다.
- 일시정지·스테이지 선택·종료: 마우스로 클릭합니다. 창의 포커스를 잃으면 일시정지합니다.
- 맵에 들어가거나 재시작하면 입력 없이 자동 반동과 모든 타이머가 진행됩니다.
- 생선은 선택 사항입니다. 공 중심이 이글루에 들어가면 즉시 정지하고 결과를 표시합니다.
- 가시 접촉·낙하·해소되지 않는 끼임은 즉시 재시작합니다. 끊긴 길은 수동 재시작합니다.

새 일반 스테이지 12개는 생선 없이 기본 7점으로 클리어합니다. 같은 점수에서는 시간이 짧을수록 좋은 기록입니다.

`최종 점수 = 7 + 생선 개수 − 생선 가시 개수`

| 점수 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|
| 등급 | B | A | S | SS | SSS |

새 튜토리얼에는 생선이 없으며 1~10번별 최고 시간을 별도로 저장합니다. 교체 전 일반 기록은 새 캠페인에 적용하지 않습니다. 일반 맵은 점수가 높을수록, 동점이면 시간이 짧을수록 좋은 기록입니다. 낮은 등급으로 클리어해도 다음 맵이 열립니다. 실패한 기록은 저장하지 않습니다.

기록은 `save_data/progress.json`에 저장합니다. 이전 버전의 튜토리얼 기록은 보존하고, 교체된 일반 캠페인은 1번부터 새로 시작합니다. 손상된 파일은 안내 후 새 기록으로 시작합니다.

## 물리와 블록

### 1회용 더블 점프 아이템

아이템은 **파랑 » 대시**와 **노랑 ↑↑ 점프** 두 종류입니다. 튜토리얼 10번에서 두 아이템을 순서대로 사용합니다. 새 일반 스테이지와 아이템 튜토리얼에서는 아이템이 48×48px이며 공 중심이 아이템 영역에 들어가면 획득합니다. 서로 다른 종류는 함께 보유하고 **대시 → 점프** 순서로 사용합니다. 같은 종류를 여러 개 먹어도 추가 횟수는 쌓이지 않습니다. 점수에는 영향을 주지 않습니다.

- 대시를 보유하면 공은 검정과 청록 테두리, 점프를 보유하면 갈색과 금색 테두리로 바뀝니다. 눈과 빨간 부리는 유지합니다. 보유한 두 종류를 모두 사용하면 기존 공 이미지로 돌아옵니다.
- 게임 화면의 같은 위치를 **0.3초 이내에 두 번 클릭·터치**하면 1회 사용합니다. UI 버튼, 화면 밖, 일시정지 중 입력은 사용으로 처리하지 않습니다.
- 키보드로도 **0.3초 이내에 같은 방향키를 눌렀다 놓고 다시 눌러** 1회 사용할 수 있습니다. 대시는 **←← / →→**로 해당 방향으로 도약하고, 점프는 **↑↑**로 사용합니다. 함께 보유한 경우 대시를 먼저 사용한 뒤 점프를 사용할 수 있습니다. 길게 누르는 자동 반복은 두 번 누르기로 처리하지 않습니다. 아이템 획득 전, 일시정지·재시작·포커스 상실 전에 누른 키는 이어서 세지 않습니다.
- 대시는 키보드의 **←← / →→**, 또는 **두 번째로 누른 위치가 공의 왼쪽인지 오른쪽인지**에 따라 방향을 정합니다. 사용 순간 살짝 위로 뜨면서 선택한 방향으로 빠르게 도약합니다. 시간제 속도 버프가 아니며, 키를 놓아도 한 번의 전진 도약을 마칩니다. 도약을 마치거나 벽·천장에 부딪히거나 착지하면 일반 이동으로 돌아갑니다.
- 현재 게임의 전진 도약 조정값은 수평 **256px(4칸)**, 최고 상승 **32px(반 칸)**입니다. 도약 거리·높이로 초기 속도와 포물선 궤적을 정합니다. 이는 이 게임의 설정값이며 모바일 원작의 정확한 물리 수치를 검증한 값은 아닙니다. **0.3초는 더블 입력을 감지하는 시간**에만 쓰입니다.
- 점프는 누른 쪽과 관계없이 수직으로 다시 도약합니다. 시작 수평 속도는 0이며 높이는 현재 위치에서 최대 192px입니다. 이후 방향키로 공중 이동할 수 있습니다.
- 공중에서도 사용할 수 있습니다. 사용한 아이템은 해당 도전에서 다시 나오지 않으며, 재시작·실패 후에는 두 아이템 모두 복원되고 보유 상태는 비워집니다.

터치스크린의 손가락 입력과 일반 마우스 입력을 처리하며, 터치에서 함께 발생하는 마우스 이벤트는 중복 사용으로 세지 않습니다.

동작 기준은 사용자가 지정한 [바운스볼/아이템](https://namu.wiki/w/바운스볼/아이템)의 대시·점프 설명입니다.
대시의 방향성·약한 상승, 점프의 수직 도약, 함께 보유했을 때의 사용 순서를 반영합니다.
원문에 없는 속도·높이의 세부 설정값은 현재 게임의 64px 블록과 물리에 맞춥니다.

### 기본 물리

논리 화면은 1600×832px입니다. 일반 맵 1~7·9~11의 물리 공간은 1600×960px(25×15칸), 8번은 2240×960px, 12번은 2240×1024px입니다. 튜토리얼은 각 문서 맵 크기를 사용합니다. 블록은 64×64px, 공 지름은 28px입니다. 전체 지형을 상단 조작 UI와 하단 안내 사이에 비율을 유지해 표시하며 창 크기 변경에도 같은 물리 좌표를 사용합니다.

| 항목 | 값 |
|---|---:|
| 일반 반동 높이 / 왕복 시간 | 96px / 0.9초 |
| 점프대 높이 / 왕복 시간 | 144px / 약 1.10227초 |
| 중력 | 약 948.148148px/s² |
| 일반 / 점프대 이륙 속도 | 약 −426.666667 / −522.557812px/s |
| 최대 수평 속력 | 약 213.333333px/s |
| 입력 가속 / 무입력 감속 | 9600 / 14400px/s² |
| 왕복 발판 속력 (최초 대비 3배) | 약 213.333333px/s |
| 발사 블록 속력 (최초 대비 3배) | 640px/s |
| 물리 / 화면 갱신 | 120Hz / 목표 60FPS |

반동은 기존 낙하 속도를 반전하지 않고 지정된 이륙 속도로 교체합니다. 일반 최대 속도 출발은 192px, 정지 출발은 약 189.63px, 점프대 최대 속도 출발은 약 235.15px를 이동합니다. 물리와 타이머는 초 단위이며 일시정지 시간은 기록에서 제외합니다.

| 블록 | 동작 |
|---|---|
| 금 간 얼음 | 윗면을 밟으면 착지 반동 후 즉시 사라짐. 옆면·아랫면 접촉으로는 파괴되지 않음 |
| 분홍 점프대 | 144px 반동. 천장 여유 172px 이상 확보 |
| 양방향 이동 발판 | 지정된 범위에서 같은 위상으로 왕복. 일반 맵 좌우 96px/s, 상하 64px/s. 이동량·속도를 공에 전달하지 않음 |
| 시간 블록 | 새 일반 맵은 3.6초 중 2.6초 활성, 블록별 시작 위상 적용. 비활성 때도 반투명 위치 표시 |
| 빨간 스위치 | 착지 시 연결 다리를 전환. 공 전체가 수평 영역 밖으로 나간 뒤 재착지해야 다시 전환 |
| 발사 블록 | 윗면 착지 시 공 중심을 블록의 세로 중심 높이에 맞춘 뒤 화살표 방향으로 640px/s 발사, 수직 속도 0·중력 해제. 방향키로 해제하면 일반 수평 속력으로 전환 |
| 가시 | 64×64px 장치. 기본 블록 위에 배치하고 아래 눈과 22px 겹쳐 표시 |

## 기획서의 미정 항목에 적용한 기준

- 기존 프로젝트의 Python/Pygame 데스크톱 실행과 별도 무화면 학습 구조를 유지합니다.
- 생선·생선 가시의 표시 폭과 중심 판정 영역은 모두 32px / 32×32px입니다. 금색 생선과 보라색 뼈 모양으로 구별합니다.
- 이글루 전체 64×64px가 비고체 도착 영역입니다.
- 공 전체가 해당 맵의 아래 경계를 벗어나는 `중심 y − 14 > 맵 높이`에서 낙하 실패합니다. 좌우·위쪽은 벽입니다.
- 공이 위에서 하강하며 평평한 윗면에 닿았을 때만 자동 반동과 착지 효과를 적용합니다. 옆면은 벽 방향의 수평 이동만 막고 수직 속도와 중력은 유지합니다. 아랫면은 상승 속도를 0으로 만듭니다. 윗면 범위 밖의 모서리는 옆으로 분리하며 자동 반동하지 않습니다. 벽을 계속 눌러도 남은 물리 시간의 이동·중력·충돌 검사를 모두 진행합니다.
- 시간 블록은 소멸 0.5초 전에 깜빡이며 비활성 중에는 반투명 윤곽만 표시합니다. 스위치의 비활성 연결 블록은 보이지 않습니다.
- 발사 제한시간은 없습니다. 어느 한 방향키 입력 또는 벽·천장 충돌로 발사를 해제합니다. 동시 입력은 해제하지 않습니다. 발사 시작부터 공 전체가 원래 발사 블록의 수평 영역을 벗어날 때까지 해당 블록만 충돌에서 제외합니다. 다른 블록과 가시의 판정은 유지합니다.
- 겹침 보정으로도 해소되지 않는 압착이 0.05초 지속되면 실패합니다. 시간 블록 생성 직후 해소 불가능한 압착은 즉시 실패합니다.
- 동일 시각의 충돌은 실패 → 수집 → 도착 순서입니다. 재시작 시 눌려 있던 방향키 상태를 비우므로 다시 눌러 이동합니다.
- 마지막 맵 결과에서 여행 완료 화면으로 이동합니다.

## 검증과 무화면 학습

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools/verify_campaign.py
.\.venv\Scripts\python.exe tools/render_campaign.py
.\.venv\Scripts\python.exe main.py --headless --stage 6 --frames 60 --screenshot stage6.png
```

일반 맵 검증기는 12개 맵의 로딩, 120Hz 시작 반동, 이동 장치, 기본 블록 위 도착 영역을 점검합니다.
3·4번은 시작점부터 이글루까지 실제 방향키 입력도 재생합니다. 나머지 일반 맵의 전체 완주 경로는 별도로 검증해야 합니다. 튜토리얼 10개는
`tools/verify_tutorials.py`로 실제 입력 경로를 재생합니다. `--headless` 실행은 별도 임시
저장소를 사용합니다. `--stage 1`~`12`는 개발용 직접 진입이며 일반 목록의 잠금에는 영향을 주지 않습니다.

Pygame 없이 학습할 때는 다음 API를 사용합니다.

```python
from pingu_ball.environment import Environment

env = Environment(stage=1)  # 새 일반 맵 기본 180초, 튜토리얼은 개별 제한시간
observation, info = env.reset()
observation, reward, terminated, truncated, info = env.step(1)
# 보유한 아이템을 왼쪽으로 사용하면서 한 틱 진행 (위로 점프는 방향 무시)
observation, reward, terminated, truncated, info = env.step(0, use_power=True, power_direction=-1)
```

행동은 `-1`(왼쪽), `0`(무입력), `1`(오른쪽)이며 한 번에 물리 1틱을 진행합니다. 관측에는 맵 크기, 공의 위치·속도, 이전 입력, 발사 상태, 생선의 위치·가치·획득 여부, 가시의 영역·삼각형, 도착 영역, 스위치, 블록의 위치·이동 범위·방향·타이머·연결 그룹이 포함됩니다. 관측은 JSON으로 직렬화할 수 있는 데이터입니다. `time_limit`을 명시하면 학습 제한시간을 직접 지정할 수 있습니다.

보상은 생선 +1, 생선 가시 −1, 성공 +7, 실패 −7이며 같은 단계의 보상은 합산합니다. 일반 이동과 제한시간 종료 보상은 0입니다. 성공·실패는 `terminated`, 제한시간은 `truncated`로 구분하며 `info['reason']`에 성공·실패 사유·시간 초과를 반환합니다. 종료 상태를 먼저 전달하고, 이후 `reset()`을 호출하면 공·수집물·블록·타이머·스위치·이전 입력을 초기화해 다음 도전을 시작합니다. AI 학습에서는 화면과 기록 파일을 사용하지 않습니다.

## 코드 구성

- `main.py`: 실행 진입점
- `pingu_ball/app.py`: Pygame 화면·입력·소리·고정 간격 게임 루프
- `pingu_ball/config.py`: 물리 기준과 계산식
- `pingu_ball/engine.py`, `geometry.py`: 화면과 독립된 게임 상태·연속 충돌
- `pingu_ball/levels.py`: 일반 맵 1~12 및 첫 튜토리얼 API 연결
- `pingu_ball/campaign.py`: 문서 기반 일반 스테이지 12개와 왕복 구간
- `pingu_ball/skin.py`: 공통 겨울 이미지와 양방향 이동 블록 렌더링
- `pingu_ball/route_driver.py`: 일반 방향키 입력으로 이동 발판 탑승·하차 경로 검증
- `pingu_ball/storage.py`: 최고 기록·해금 저장
- `pingu_ball/environment.py`: 학습용 reset/step
- `pingu_ball/validate.py`, `tests/`: 경로·물리·UI 회귀 검증
- `assets/`: 남극 배경, 겨울 테마 이미지, 맵 원본 미리보기

`output/`은 다시 생성할 수 있는 빌드·검증 산출물 폴더입니다. 폴더를 정리해도 소스와 자산으로
다시 빌드할 수 있으며, 배포용 실행파일은 `output/executable/PinguBall.exe`에 있습니다.
튜토리얼 보존 검증 기준은 `tests/fixtures/tutorial_baseline.json`에 보관합니다.
