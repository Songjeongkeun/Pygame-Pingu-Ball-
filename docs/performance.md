# 블록이 많은 스테이지의 프레임 처리 개선

2026년 10월 20일 같은 PC에서 실제 게임 자산을 사용해 측정했다.
화면 그리기와 물리 계산을 합친 프레임 처리 시간이며, 60fps 대기 시간은 제외했다.

| 스테이지 | 수정 전 평균 | 수정 후 평균 |
|---|---:|---:|
| 5 | 18.23ms | 12.68ms |
| 8 | 17.98ms | 12.47ms |
| 11 | 25.17ms | 13.60ms |
| 12 | 29.32ms | 15.18ms |

12번 평균 처리 시간을 약 48% 줄였다. 이 측정에서 수정 후 12번의 95백분위 처리 시간은
17.79ms다. 모든 기기와 장면에서 60fps를 보장하는 수치는 아니다.
측정은 SDL 더미 화면, 창 1000×520, 8프레임 준비 후 120프레임, 좌우 입력 없음,
소리 꺼짐 조건이다. 실제 창의 화면 전송 시간과 운영체제의 순간 부하는 다를 수 있다.

먼 장애물은 보수적인 범위 검사로 먼저 제외하고, 가까운 물체는 기존의 연속 충돌 판정으로 검사한다.
이동·회전 장애물은 상대 이동과 기존 시간 샘플을 유지한다. 벽에 닿지 않은 발판의 속도 탐색과
시간 블록 이외의 이전 활성 상태 계산도 줄였다. 지형 위 블록을 매번 전체 검색하던 부분은
프레임별 위치 집합으로 바꿨다. 화면 축소 버퍼, 반복되는 글자와 패널을 재사용하며 캐시는 크기를 제한한다.

120Hz 물리 주기, 반동과 이동 속도, 맵 배치는 유지한다. 물리 단계를 생략하거나 누적 시간을 버리지 않는다.
수정 전후 20,000개 무작위 충돌 사례와 4개 맵의 1,440틱 기록이 일치했고,
같은 시점의 4개 맵 화면 픽셀도 일치했다. 회귀 테스트에는 필터를 끈 충돌 판정과의 비교,
고속 이동·접선 접촉, 화면 크기 변경과 버퍼 재사용을 포함한다.

```powershell
.\.venv\Scripts\python.exe -B tools/benchmark_performance.py --frames 120
.\.venv\Scripts\python.exe -B -m unittest discover -s tests
```

성능 측정 결과는 `output/performance/benchmark.json`에 저장한다.
